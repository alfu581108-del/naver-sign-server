# 비리프엔젤 블로그 4채널 발행 (런북 v4)

노션 「📤 블로그 4채널 발행 런북 v3」(3c0b9185-756d-816b-8dc0-f976b2a1f7d4)를 스킬로 옮기고,
2026-10-02 마리님 지시(3자회의)와 9/29 사실 정정을 반영한 판이다.
노션 런북과 이 스킬이 다르면 **이 스킬이 최신**이다. 다만 노션 쪽이 더 최근에 수정됐다면 노션을 따르고 이 스킬 갱신을 제안한다.

## 한눈에

```
글감 큐 조회 → (초안 없으면) 3자회의로 4채널 초안 → 클로드 최종검토 → 미리보기 PNG
→ 채널별 발행(가능한 경로만) → 큐·아카이브 기록 → 보고
```

한 번 실행에 **글감 1건**만 처리한다. 밀린 게 많아도 마리님이 "몰아서"라고 하지 않는 한 1건.
이유: 검수 품질이 떨어지고, 같은 날 여러 편이 한꺼번에 올라가면 검색엔진이 스팸처럼 본다.

## 0. 시작 전 확인 (환경 점검)

이 스킬은 실행 환경마다 쓸 수 있는 경로가 다르다. 시작할 때 아래를 확인하고, 안 되는 채널은 **억지로 우회하지 말고** 보고에 "왜 못 했는지 + 마리님이 할 일"을 적는다.

| 확인 | 방법 |
|---|---|
| 노션 접근 | Notion MCP (`notion-fetch`, `notion-query-data-sources`) |
| 브라우저 | `mcp__claude-in-chrome__*` 또는 `mcp__remote-devices__*` 도구가 있는가 (없으면 클라우드 세션) |
| GPT / 제미나이 API | 환경변수 `OPENAI_API_KEY`, `GEMINI_API_KEY` 존재 여부 (`env | grep -c KEY` 식으로 **값은 절대 출력 금지**) |
| 채널 토큰 | `references/channels.md`의 채널별 "필요한 것" |

채널별로 가능한 발행 경로와 우선순위는 **`references/channels.md`** 에 있다. 발행 단계 전에 반드시 읽는다.

## 1. 발행 대상 조회

글감 큐 데이터소스 `collection://85bc8c06-2587-4c2c-b5db-71acae2ca49b` (한글 컬럼은 큰따옴표):

```sql
SELECT url, "글감", "순번", "티스토리", "블로그스팟(영문)", "네이버", "워드프레스(자료형)", "발행 메모", "핵심 질문", "티어", "유도 상품"
FROM "collection://85bc8c06-2587-4c2c-b5db-71acae2ca49b"
WHERE "티스토리"='초안완료' OR "블로그스팟(영문)"='초안완료' OR "네이버"='초안완료' OR "워드프레스(자료형)"='초안완료'
ORDER BY "순번" LIMIT 1
```

- 결과가 없으면 → 초안이 없는 다음 순번을 찾아 **2. 3자회의**로 간다.
- 초안 자식 페이지 4개: "📄 티스토리 초안", "📄 네이버 초안", "📄 Blogspot(EN)", "📄 워드프레스 초안".
- **9/29 이전에 쓴 초안**(순번 9~15 등)은 발행 전에 반드시 **3. 최종검토**를 다시 돌린다. 사실 정정 이전 문장이 남아 있을 수 있다.

## 2. 초안 작성 = 3자회의 (2026-10-02 마리님 확정)

역할은 바꾸지 않는다. 자세한 프롬프트·호출 방법은 **`references/three-party-meeting.md`**.

| 역할 | 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| ✍️ 집필 | **GPT** | 채널별 4편 본문을 쓴다 (마리님: "글솜씨는 GPT가 더 좋다") | 사실을 새로 만들지 않는다. 브리프에 없는 수치·인증·경력은 `[확인 필요]`로 비워 둔다 |
| 🔎 정보탐색·검증 | **제미나이** | 집필 중 막히거나 검수가 필요한 주장(수치·연구·제도·염료 지식)을 검색 근거와 함께 확인 | 글을 고쳐 쓰지 않는다. 근거(URL)와 판정만 돌려준다 |
| ⚖️ 최종검토 | **클로드** | ① 브랜드 핏 ② 없던 얘기(환각) ③ 금기 ④ 채널 톤을 판정하고 걸린 문장만 고친다 | 처음부터 다시 쓰지 않는다. 다시 써야 하면 GPT에 돌려보낸다 |

진행 순서:
1. **클로드가 브리프를 만든다** — 글감·핵심 질문·티어·유도 상품 + `references/fact-guard.md`의 확정 사실 중 이 글에 필요한 것만 + 채널별 포맷 규칙. 브리프에 들어간 사실이 GPT가 쓸 수 있는 사실의 전부다.
2. **GPT 집필** — 4채널 초안. 채널 포맷은 `references/three-party-meeting.md` §채널 포맷.
3. **제미나이 검증** — GPT 초안에서 외부 사실 주장(브랜드 외 일반 지식)을 뽑아 확인. 근거 없는 주장은 삭제 또는 완화 제안.
4. **클로드 최종검토** — 아래 3절. 결과가 "불합격"이면 GPT에 지적사항과 함께 재집필 요청(최대 2회). 3회째도 불합격이면 멈추고 마리님께 보고.
5. 노션 큐 행 아래에 초안 4페이지를 만들고, 각 채널 상태를 '초안완료'로, "발행 메모"에 `3자회의: GPT(모델명)/제미나이(모델명)/클로드 검토 YYYY-MM-DD`를 남긴다.

**GPT나 제미나이를 쓸 수 없을 때** (키 없음·API 오류·브라우저 없음): 클로드가 몰래 대신 쓰지 않는다. 마리님 지시를 어기는 것이고, 나중에 어떤 글이 3자회의를 거쳤는지 구분이 안 된다. 대신:
- 보고에 "3자회의 불가 — 이유"를 적고 멈춘다. 또는
- 마리님이 그 회차만 허락하면 클로드가 쓰되, 발행 메모에 `클로드 단독(3자회의 미적용, 마리님 승인)`을 남긴다.

## 3. 클로드 최종검토 (매 회차 필수 — 초안이 이미 있어도)

판정 기준은 `beleft-brand-voice-editor`의 판정 모드 4축을 따르고, 블로그용으로 아래를 더한다. 사실 기준은 **`references/fact-guard.md`**.

| 축 | 블로그에서 특히 볼 것 |
|---|---|
| ① 없던 얘기 | 문장마다 "브리프·fact-guard·제미나이 근거 중 어디로 되돌아가나". 1인칭 경험, 기간(N년), 유일성(국내 유일·세계 최초), 수치(폐수 80% 등), 인증 귀속, 연구 인용은 하나씩 확인 |
| ② 금기 | 싸다·저렴·가성비·할인·세일·특가·최저가·무조건·100%·특허·세계 최초·완치·치료, 경쟁사 언급, 최상급 표현(전 세계 유일·세계 최고 난도) |
| ③ 브랜드 핏 | "더하기 이전에 덜어내기", 아이가 맘놓고 실수해도 되는 정원. 겁주기·완벽주의·과장 X. 5키워드(신념·클래식함·정성스러움·포근함·자연주의) |
| ④ 채널 톤 | 티스토리=정보형+따뜻함, 네이버=1인칭 대화형("~해보려고요"), 워드프레스=자료형(표·수치·정의), 블로그스팟=영어 원어민 문장(번역투 X) |

출력:
```
판정: 합격 / 보류(고치면 됨) / 불합격(GPT 재집필)
채널별 ①②③④ ✅|⚠️|❌ — 걸린 문장 그대로 → 이유 → After
[마리님 확인 필요: …]  ← 근거가 없어 판단을 못 한 것
```
- ①에 ❌가 하나라도 있으면 그 채널은 불합격. 발행하지 않는다.
- 모르면 ⚠️ + `[마리님 확인 필요]`. 추측으로 통과시키지 않는다.
- 검토 후 `beleft-humanizer`로 AI티 마지막 교정은 선택(한국어 3채널만).

## 4. 이미지

- 초안의 `🎨 IMG:` 마커마다 이미지가 필요하다. **제품 실물이 나와야 하는 자리는 AI 생성 금지** — 실사진(`*화보컷_웹` / `*디테일컷_웹`)을 쓴다.
- 생성 경로(우선순위): ① Gemini API 이미지 모델(`GEMINI_API_KEY`) ② Gemini 웹(gemini.google.com, 마리님 계정, 브라우저 필요) ③ 생략.
- 생략하면 마커는 지우고 보고에 "이미지 생략" 1줄.
- 여러 채널에 같은 이미지를 쓸 때는 워드프레스 미디어에 먼저 올려 그 URL을 재사용해 왔다(2026/09 경로). 바뀐 방식이 있으면 `references/channels.md`를 따른다.
- API 키 값은 어떤 로그·노션·보고에도 출력하지 않는다.

## 5. 미리보기 PNG (매 회차, 2026-08-21 마리님 확정)

초안과 이미지가 준비되면 2장을 만들어 SendUserFile로 전달한다.
- `preview-N-발행미리보기.png` — 4채널 카드 요약(채널 배지·제목·실제 이미지·요지 2~3문장·발행상태 배지)
- `preview-N-네이버초안.png` — 네이버 초안 **전문**을 네이버 블로그 모양으로 렌더한 세로형. 요약·발췌 금지(마리님이 이걸 보고 복붙 발행)
- 방법: HTML → Playwright(scale 2, full_page) → PNG. 템플릿이 환경에 없으면(`/root/workspace/preview3/` 등) 새로 만들되 위 구성을 지킨다.
- 전달 전 맞춤법·오타 1회 점검. 발견하면 노션 초안부터 고치고 렌더.

## 6. 채널별 발행

**`references/channels.md`를 읽고** 이 환경에서 가능한 경로를 고른다. 원칙:
- 상태가 '초안완료'이고 3절에서 **합격**한 채널만 발행한다.
- 채널마다 재시도는 최대 2회. 실패하면 다음 회차로 넘긴다(자동 이월).
- 발행 직전 금기어 자동 스캔: `python scripts/taboo_scan.py <본문 파일>` — 걸리면 그 채널은 중단하고 보고.
- 티스토리 카테고리: 배내박스·기록·선물 티어 → "구매 가이드·육아", 제로다잉·아토피·안전·인증 티어 → "안전성·천연염색".
- 네이버는 자동 발행 경로가 없다. 노션 초안 링크 + 네이버 미리보기 PNG를 드리고, 마리님이 발행한 뒤 상태를 바꾼다.

## 7. 기록

- 큐 행: 발행된 채널은 '발행완료', "발행 메모"에 날짜·채널별 URL 추가. 네이버는 마리님이 발행 후 직접 변경(클로드는 '초안완료' 유지).
- 티스토리를 발행했으면 「📝 티스토리 발행 아카이브」 `collection://78f335ec-8848-4719-870c-55fc4aa0f4be`에 행 추가: 제목·URL·발행일·상태='게시 완료'·소재 카테고리·타깃 키워드(핵심 질문 기반).
- 긴 노션 문서를 만든 뒤에는 `beleft-text-integrity`로 한글 깨짐을 검사한다.
