# 비리프엔젤 모바일 "큰 글씨" 대응 패치 (zoomfit v1 · 2026-09-29)

## 진단: 원인은 하나, 증상은 열 가지

마리님 스크린샷의 글자는 설계값보다 **약 1.5~1.7배 크게** 렌더되고 있습니다. 카카오톡 인앱 브라우저 주소창의 「가가」(글자 크기) 또는 폰 글꼴 크기 설정 때문입니다.
09-14 모바일 QA는 **375px · 기본 글자 크기**로만 측정해서 이 조건을 통과시키지 못했습니다.
주 고객인 30~40대 엄마들 상당수가 큰 글씨를 씁니다. 그래서 확대를 **막지 않고, 확대돼도 무너지지 않게** 고치는 것이 맞습니다.
`user-scalable=no`나 글자 확대를 무시하는 방식은 접근성을 해쳐서 쓰지 않았습니다.

기준 기기는 갤럭시 S21 Ultra(SM-G998N)입니다. CSS 뷰포트 384×854, DPR 2.8125, 20:9 비율, 3버튼 내비게이션입니다.

## 적용 방법

1. `M_zoomfit_꼬리블록_v1.txt` 내용 전체를 복사합니다.
2. 카페24 어드민 → 디자인(모바일) → **공통 레이아웃**(`/layout/basic/layout.html`) 파일 **맨 끝**에 붙여넣습니다.
3. **메인 레이아웃**(`/layout/basic/main.html`)에도 똑같이 붙여넣습니다. 떠 있는 버튼과 헤더가 메인에도 있기 때문입니다.
4. PC 파일은 건드리지 않습니다.

**되돌리기**: 붙여넣은 `<style id="bel-zoomfit-css">`부터 `<script id="bel-zoomfit-js">` 블록 끝까지 삭제하면 됩니다.

## 동작 방식과 한계 (솔직하게)

- 이 클라우드 환경에서는 m.beleftangel.com 접속이 막혀 있고(프록시 403), 스킨 원본 파일도 없습니다. 그래서 카페24 클래스명을 추측하지 않고 **화면 글자로 요소를 찾는 방식**을 택했습니다. 예를 들어 "구매하기", "관련상품", "사이즈 추천받기", "CUSTOMER CENTER"라는 글자로 요소를 찾아 `bel-*` 클래스를 붙입니다. 요소를 못 찾으면 아무것도 하지 않으므로 페이지가 깨지지는 않습니다.
- 검증은 실제 사이트가 아니라 스크린샷 구조를 흉내 낸 목업(`test/mock-detail.html`)으로 했습니다. Playwright로 384×854 뷰포트에서 글자 100/130/170%를 적용해 확인했습니다. 결과는 가로 넘침 408px → 384px(없음), 구매하기 버튼 화면 안, 대상 16종 전부 인식입니다.
- **라이브에 붙인 뒤 꼭 확인할 것**: 카톡 인앱에서 「가가」를 최대로 올린 상태로 상품상세·검색·푸터를 한 번씩 보기. 헤더가 스크롤에 따라 숨고 나오는지 확인. 햄버거 메뉴를 연 상태에서 스크롤해도 문제없는지 확인.
- `M_상품상세_v12.txt`와 `M_공통_레이아웃_v6.txt`를 주시면 글자 탐색 대신 정확한 셀렉터로 바꿔 더 가볍게 만들 수 있습니다.

## 코드로 안 고친 것 (어드민 몫)

- 상품명 옆 빨간 **'추천' 아이콘**은 크림·세이지 톤과 충돌합니다. 어드민 → 상품 아이콘에서 교체하거나 끄는 것을 권장합니다.
- 상세에서 **27,800원이 두 번** 나옵니다(상단 가격 + 판매가 행). 판매가 행은 할인이 있을 때만 보이도록 하는 것을 권장합니다.
- 검색 결과 개수 "(3)"과 페이지 번호가 파란색입니다. 카페24 기본 스킨 색이라 다음 회차에 세이지로 바꾸겠습니다.
